About the library

A library, not another social network.

FTC-Library exists to keep useful engineering work from disappearing when a season ends. It is a centralized, searchable, community-maintained collection of resources that teams can actually reuse.

Why this exists

Every season, teams solve hard problems: a drivetrain that finally drives straight, an autonomous routine that survives a crowded field, a portfolio structure that communicates the engineering process clearly. Too often that work lives in one team's drive folder or disappears with a graduating class.

The library gives that work a stable home. It does not try to rank teams, host discussions, or become a destination for daily updates. It organizes resources, preserves attribution, and makes them easier to find next season.

What belongs in the library

A resource should be useful to another team. It can be a finished artifact, a reference, or a guide that explains a process.

  • Engineering Portfolios: published portfolios, notebook excerpts, and judging resources.
  • CAD Models: STEP, STL, native CAD, field models, mechanisms, and reusable assemblies.
  • Programming: libraries, autonomous routines, vision tools, SDK extensions, and example code.
  • Electronics: wiring references, control system guides, sensor notes, and hardware documentation.
  • Documentation: game manuals, technical guides, checklists, and season reference material.
  • Tools and Resources: dashboards, calculators, templates, and other build-season utilities.

Rule of thumb: if another team could learn from it, build on it, or avoid repeating a mistake because of it, it belongs here.

How review works

The library deliberately uses GitHub instead of a custom backend. That keeps the project cheap to run and easy to audit.

  1. Submit through the form or GitHub issue template. The submission includes files or links plus the required metadata.
  2. A maintainer checks the basics. Team, season, category, description, attribution, license, and access links are reviewed.
  3. Approved resources are committed. Files are stored in the repository and the resource is added to data/resources.json.
  4. The library updates automatically. GitHub Pages serves the site, and client-side search reads the updated JSON.

Attribution and licensing

Every resource must name its creator or original source and state a license. If a submission is adapted from another team's work, say so. If the license is unclear, do not submit the files; link to the original instead.

The site code is licensed under MIT. Resources keep their own licenses, and nothing in this library overrides the terms chosen by a resource's creator.

Maintainers can find the detailed schema, review checklist, and file layout in the contributing guide.
