Contribute

Share a resource with the community.

Fill in the details below and the site will prepare a GitHub issue for you. Attach your files to that issue, and a maintainer will review the submission. No account on this site is required.

Resource basics

Start with the information someone would use to find this resource.

Use the team that created the resource, even if another team is submitting it.

Description and discovery

Help teams understand what the resource is and when it is useful.

20–1000 characters. Be specific about the season, mechanism, or software version where it applies.
Comma-separated. Tags help with search but are not required.
One public http(s) URL per line. You will attach files to the GitHub issue after it opens.
Files: after GitHub opens the issue, drag PDFs, STEP, STL, source archives, images, or documentation into the issue comment box. GitHub accepts files up to 25 MB each. For larger files, link to a public drive, GitHub release, or Onshape document.

Attribution and license

Every resource must credit its creator and state how others may use it.

Credit the team or person who made the resource. Mention if it is adapted from another source.

What happens next

  • A maintainer reviews the metadata, attribution, and license.
  • If the resource is approved, it is added to the repository and JSON data.
  • The resource appears on the library page, usually with a direct link.
  • You may be asked to clarify a link, license, or file before approval.

Rather use GitHub directly?

You can open the structured GitHub issue form and fill it out manually.
